## 1. 현황 진단: 프로토타입과 Hospital SW flow의 차이

| 구분 | Hospital sw flow 요구 | 프로토타입 v0.1 | 차이 |
|---|---|---|---|
| Level 1 (항목정의서·메타데이터) | 메타데이터 기준 표준 매핑과 구조 정리 | **구현됨**: 6개 표준 매핑, 암종 패키지, DCAT | 매핑 품질 보강 필요(§3) |
| Level 2 (Raw·로그 데이터) | 로우 항목 전개 → 표준 매핑 → **가명처리 실행 코드 생성** | 브라우저에서 데이터를 직접 변환(부가 기능) | **코드 추천 방식이 없음** |
| 원본 미수정 원칙 | 원본을 직접 바꾸지 않고 SQL·Python·Regex를 추천하며, 사용자가 로컬에서 실행 | 원본 파일은 읽기만 함. 다만 결과물이 '변환된 데이터'임 | 산출물을 '코드 + 해설'로 바꿔야 함 |
| FR-01 로우 항목 매핑 | 전개되지 않은 로우 항목 → 표준 항목 자동 매핑 | 별칭·정규화 매칭(규칙) | 퍼지 매칭·샘플값 기반 추론·LLM 보조가 없음 |
| FR-02 가명처리 추천 | 삭제·값 변환 등 기법 추천과 해설 | 식별자 해시, 생년 연도화만 있음(고정 규칙) | **항목별 기법 사전과 추천 엔진이 없음** |
| FR-03 정형·비정형 샘플 분석 | 정형 10행·비정형 1쪽 샘플 → Regex/SQL/Python | 정형 값 검증만 있음 | 비정형 PII 탐지와 코드 생성이 없음 |
| FR-04 DICOM 헤더 비식별화 | pydicom 스크립트 생성 | 없음 | 신규 |
| NFR-01 폐쇄망 | 외부 연결 없이 동작 | CSP `connect-src 'none'` | 충족. 로컬 LLM 연결 시 예외 설계가 필요 |
| NFR-02·03 소형 LLM, 경량 | 7B~14B GGUF/AWQ, 엔진 100~200MB, CPU 비동기 | LLM 없음, 단일 HTML 2.5MB | 어댑터 방식으로 붙임(§4.3) |
| NFR-04 환경 무의존 | Standard SQL·Python 출력 | 해당 없음 | 코드 템플릿 설계 |
| 품질·이력 | Human-in-the-loop, 로컬 감사이력, 중앙 규칙 동기화 | `규칙승인(후보)` 태그, 변환로그 | 승인 UI, 감사 이력, 규칙팩 버전 관리가 없음 |

**결론:** v0.1은 Hospital SW의 **Level 1 엔진**으로 그대로 쓸 수 있습니다. v0.2의 핵심은 **Level 2 "가명처리 코드 추천" 모듈**을 붙이는 것과, 그 바탕이 되는 **매핑 품질 보강**입니다.

## 2. 개발 원칙

1. **원본 미수정.** 산출물은 `CREATE VIEW` / `CREATE TABLE … AS SELECT`(새 스키마), Python(입력은 읽기 전용, 출력은 새 파일), Regex 함수입니다. `UPDATE`·`DELETE`·`ALTER`·덮어쓰기 코드는 생성하지 않고, 생성기 자체 검사로 차단합니다.
2. **규칙 우선, LLM 보조.** 결정적 규칙과 내장 템플릿이 성능 하한선입니다(Flow 6.1 '기본 성능 유지'). LLM은 후보 추천과 해설만 맡고, 출력은 JSON 스키마로 검증한 뒤 받아들입니다.
3. **Human-in-the-loop.** 모든 추천은 `후보 → 검토 → 승인/수정/반려` 상태를 거칩니다. 승인되지 않은 항목은 코드 패키지에 넣지 않습니다.
4. **무설치 유지.** 기본 배포본은 단일 HTML 1개입니다. LLM 연동은 별도 빌드(`--llm`)로만 켭니다.
5. **추적성.** 생성 코드마다 규칙 ID, 항목 ID, 규칙팩 버전, SHA-256을 주석으로 넣고 감사 이력에 남깁니다.

## 4. 기능 개발 범위

### 4.1 Level 2 — 가명처리 코드 추천 모듈 (FR-01~03, 신규 탭 `④ 가명처리 코드`)
1. **입력:** 원천 컬럼 목록 + 샘플 **최대 10행**(정형) / 비정형 텍스트 **최대 1쪽**. 샘플은 화면에서만 쓰고 산출물에 넣지 않습니다.
2. **로우 항목 전개:** 복합 컬럼(예: `TNM=pT2N1M0`, `ER/PR/HER2`)을 하위 항목으로 나누는 규칙을 둡니다. 결과는 기존 매퍼(별칭 → 정규화 → 퍼지 → 샘플값 패턴)로 넘깁니다.
3. **가명처리 기법 사전** (`spec/deid_rules.json`, 규칙 ID 부여)

| 항목 역할(`role`) / 탐지 패턴 | 기본 기법 | 대안 |
|---|---|---|
| 직접식별자(성명, 주민번호, 전화, 주소 상세) | 삭제(Delete) | 마스킹 |
| 기관 환자번호·등록번호 | 솔트 + SHA-256 가명키 | 일련번호 대체(매핑표는 기관 보관) |
| 생년월일 | 연도만 남김 | 5세 구간화 |
| 사건 일자(진단·수술·검사) | 날짜 이동(환자별 일정 offset) | 진단일 기준 경과일(ARGO 호환) |
| 나이·수치 극단값 | 상·하단 코딩(Top/Bottom coding) | 구간화(Binning) |
| 희귀 범주(소수 셀) | 범주 통합 | 삭제 |
| 자유문 | Regex PII 치환 `[ANONYMIZED]` | 컬럼 삭제 |

4. **코드 생성기** (템플릿 + 파라미터, 출력 전 자체 검사)
   - Python(pandas): `pathlib`·`r"C:\…"` 경로, `encoding="utf-8-sig"` 입출력, CP949 입력은 자동 감지 후 대체 처리, 원본은 읽기만 하고 결과는 새 파일.
   - Standard SQL: `CREATE VIEW deid.<table> AS SELECT …`(ANSI 기준. 해시·날짜 함수는 기관 DB 방언(MSSQL·Oracle·PostgreSQL)별 어댑터로 분리).
   - Regex: Python `re` 함수 + 브라우저 안에서 샘플로 바로 시험해 보는 기능(탐지 건수 표시).
   - 금지어 검사: `UPDATE|DELETE|DROP|ALTER|TRUNCATE|to_csv(<입력경로>)`가 있으면 생성을 거부합니다.
5. **산출물:** `가명처리코드_<암종>_<일시>.zip` = `deid.py`, `deid_<방언>.sql`, `regex_pii.py`, `requirements.txt`, `run.bat`(venv python 직접 호출), `README_실행안내.md`, `매핑_가명처리_요약.json`, `감사이력.jsonl`.

### 4.2 FR-04 DICOM 헤더 비식별화 스크립트 생성
- DICOM PS3.15 Basic Profile 태그 목록을 내장합니다. 옵션은 UID 재생성, 날짜 이동, private tag 삭제, burned-in 경고입니다.
- 산출물은 `deid_dicom.py`(pydicom, 폴더 일괄 처리, `FileNotFoundError`·`InvalidDicomError` 처리, 처리 로그 CSV)입니다. 브라우저는 DICOM 파일을 읽지 않고 **설정 → 스크립트** 생성만 합니다.

### 4.3 로컬 LLM 어댑터 (선택 빌드, NFR-01~03)
- `python tools/build.py --llm`으로 빌드하면 CSP를 `connect-src http://127.0.0.1:11434 http://127.0.0.1:1234`로 바꿉니다. **loopback만 허용**하고, 기본 배포본은 `'none'`을 유지합니다.
- Router/Adapter: `llm.js`에 `ollama`(`/api/chat`)와 `openai-compatible`(LM Studio, 중앙 API) 두 가지 어댑터를 둡니다. 중앙·외부 API는 설정에서 명시적으로 켜고 경고를 띄웁니다.
- 프롬프트는 `docs/04_맞춤형_프롬프트.md`의 P1~P5를 내장합니다. 출력은 JSON 스키마로 검증하고, 실패하면 1회 재시도한 뒤 규칙 결과로 대체합니다.
- CPU 환경: 요청을 비동기 큐로 처리합니다. 진행 표시와 취소를 지원하고, 항목을 20개 단위로 나눠 보냅니다.
- 샘플값을 LLM에 보낼지는 기본 **OFF**로 둡니다. 켜는 경우에도 loopback 전용 모델에만 보냅니다.

### 4.4 Human-in-the-loop · 감사 이력 · 규칙팩
- 매핑과 가명처리 추천 표에 `승인/수정/반려` 열과 근거 메모를 둡니다. 일괄 승인은 신뢰도 '높음'에만 허용합니다.
- **로컬 감사 이력:** 화면 동작을 `audit.jsonl`로 내려받고, IndexedDB에 임시 보관합니다. 기록 항목은 시각, 작업자 표기, 규칙팩 버전, 입력 컬럼 해시, 채택·수정 내역입니다.
- **중앙 규칙팩:** `rulepack_<버전>.json`(매핑 규칙, 가명처리 사전, 정규식 패턴, SHA-256 서명값)을 불러오고 내보냅니다. 버전이 다르면 차이를 보여 줍니다.

### 4.5 v0.1 보수 항목
- README 수치를 맞춥니다: 배포본 크기(1.4MB → 실제 2.5MB), 검토 대상(168 → 171), mCODE 프로파일 수(37/38).
- 재현성: `build_spec.py`·`mcode_dict.py`가 상위 폴더와 깊은 `outputs/…/source_review/` 경로의 원본을 참조합니다. 원본 사본과 SHA-256 목록을 `spec/sources/`에 두고, 경로를 인자로 바꿀 수 있게 합니다.
- '부가: 환자 데이터 변환'은 **합성·더미 데이터 검증용**으로 위치를 바꿉니다. 실데이터는 §4.1 코드 방식으로 처리하도록 안내 문구를 넣습니다.
