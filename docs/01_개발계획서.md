# K-CURE 표준변환기 프로토타입 개발계획서

- 작성일: 2026-10-06
- 기준 자료: `중개포털_SW겸용_항목정의서_KRmCODE_v2.4.xlsx` (1,255 항목, 규칙 140개 승인, L3 전문가검증 0건)
- 보조 자료: `중개포털_SW겸용_항목정의서_KR_mCODE_260831_V1.2.xlsx` (원천 별칭·KR CDI 대응유형·프로파일 후보·코드표),
  KR CDI V3 / KR Core V2 상세설명서, 「국가데이터 통합 연계를 위한 데이터 카탈로그 표준 가이드 v1.0」(NIA, 2025.10)

## 1. 목표

K-CURE 9개 암종 항목(원천 데이터 및 항목정의)을 다음 세 표준으로 변환하는 **무설치 SW 프로토타입**을 만든다.

| 대상 | 변환 결과 | 근거 |
|---|---|---|
| KR CDI V3 (내용표준) | 14분류·80항목 구조의 교류 데이터(JSON/CSV) + 적합성(R/R2/O) 리포트 | v2.4 `KR_CDI_Class/Element/필수`, 20·21번 시트 |
| KR Core V2 (전송표준, FHIR R4) | FHIR R4 transaction Bundle (meta.profile에 KR Core 또는 KR-mCODE 후보 프로파일) | v2.4 `KR_Core_Profile/FHIR_Path/판정`, 12번 프로파일 후보 |
| DCAT 2.0 (메타데이터) | DCAT-AP 2.1 기반 국가 데이터 카탈로그(NDI 확장 포함) RDF/XML·Turtle·JSON-LD | NIA 카탈로그 표준 가이드 [표 5]·[표 6] |

## 2. 무설치 구현 방식

- **단일 HTML 파일 1개**(`dist/KCURE_표준변환기.html`). 더블클릭하면 Edge/Chrome에서 실행된다.
- 설치·관리자 권한·인터넷이 필요 없다. 외부 라이브러리는 쓰지 않고, XLSX 해석기와 SHA-256도 직접 구현해 넣었다.
- **환자 데이터는 PC 밖으로 나가지 않는다.** CSP(`connect-src 'none'`)로 네트워크 전송을 원천 차단한다.
- 명세(1,255 항목 매핑)는 HTML 안에 내장한다. 항목정의서가 개정되면 앱에서 새 xlsx를 불러와 명세를 즉시 교체할 수 있다.
- 지원 브라우저: Edge/Chrome 103 이상 (`DecompressionStream('deflate-raw')` 사용).

## 3. 기능 범위

### 3.1 데이터 변환 모드 (원천 데이터 → 3개 표준)
1. 입력: CSV/TSV/XLSX. 형식은 1행 1환자(wide). 같은 환자가 여러 행에 있어도 된다.
2. 컬럼 자동매핑: 표준항목명, 원천 항목명(암종별 ASIS 별칭), 정규화 이름을 차례로 대조한다. 그다음 수동으로 보정한다.
3. 값 변환: 날짜(YYYYMMDD → YYYY-MM-DD), 코드(허용값 사전 → FHIR code/Coding), 여부(Y/N/U → boolean·status), 수치(Quantity + 단위).
4. 가명처리(기본 ON): 환자 식별자를 솔트를 넣은 SHA-256으로 치환한다.
5. 출력: FHIR Bundle, KR CDI 교류데이터, DCAT 카탈로그(데이터셋 프로파일 통계 포함), 변환·검증 로그, 매핑 설정(JSON, 재사용용).

### 3.2 항목정의 변환 모드 (데이터 없이)
- 9개 암종별 DCAT Dataset 카탈로그. 항목 정의는 `ndi:profile`에 변수 사전으로 넣는다.
- FHIR ConceptMap 2종(K-CURE→KR CDI, K-CURE→KR Core 경로)
- 매핑 명세 CSV

## 4. 변환 규칙 요약

### 4.1 FHIR (KR Core)
- 리소스 그룹: `(리소스유형, 대분류, 중분류)` 단위로 한 환자·한 행에 1개 인스턴스를 만든다.
- 경로별 처리
  - 값 경로(`Observation.value[x]`, `Condition.code` 등): Observation은 항목 1개당 1개 리소스를 만든다. code는 K-CURE 항목 코드다.
  - 수식 경로(`effectiveDateTime`, `method`, `bodySite`, `valueQuantity.unit`): 같은 그룹의 값 리소스에 일괄 적용한다.
  - 상태 경로(`*.status`·`verificationStatus`, 여부 항목 74건): **별도 리소스로 분리**한다(code.text=항목명). 주 리소스의 상태를 오염시키지 않기 위해서다. 로그에 "매핑 검토 권장"으로 남긴다.
  - R4에 없는 경로(예: `AdverseEvent.description`)와 `extension:*`: `http://khis.kr/fhir/kcure/StructureDefinition/item-{항목ID}` 확장으로 보존한다.
  - 같은 그룹 안에서 단일값 경로가 충돌하면 리소스 인스턴스를 추가로 만든다.
- 필수 요소(R4 min=1)가 원천에 없으면 기본값으로 보완한다(`status=unknown` 등). 보완한 내역은 전부 로그에 남긴다.
- 프로파일: KR Core 공식 프로파일은 KR Core canonical, "KR Core 미정의"는 KR-mCODE 후보 프로파일(PRF-xxx) canonical을 쓴다.

### 4.2 KR CDI
- `KR_CDI_Element`가 배정된 항목(186개)만 대상이다. 직접대응/부분대응을 구분해 표기한다.
- 환자별 14분류 구조 JSON과 long-format CSV를 만든다.
- 적합성: 데이터셋이 다루는 분류에서 R(필수) 항목이 빠졌는지 점검하고, 80항목 커버리지를 보고한다.

### 4.3 DCAT (국가 데이터 카탈로그 표준)
- Catalog / Dataset / Distribution / DataService / CatalogRecord + NDI 확장(DataProduct, Quality)
- 필수 속성 검증: Catalog(title, description, publisher), Dataset(title, description), DataService(title, endpointURL),
  Distribution(accessURL), CatalogRecord(primaryTopic, modified), NDI(viewCnt, downloadCnt, srvcType, pltfrmAccessToken)
- `dcat:theme`=건강의료(분류코드 8), `dct:conformsTo`=KR CDI V3·KR Core V2
- 항목 수준 정보는 `ndi:profile` JSON(변수 정의·표준매핑·결측률 통계)에 넣는다. **환자 단위 샘플은 넣지 않는다.**

## 7. 한계(프로토타입 범위)

- 매핑은 v2.4의 **규칙승인(후보)** 단계를 그대로 따른다. 항목별 의미검증(L3)은 하지 않은 상태라서 출력물도 "후보" 등급이다.
- FHIR 검증은 내장 구조검증(필수요소·자료형·참조 무결성)까지만 한다. 공식 검증은 HL7 FHIR Validator + KR Core 패키지로 별도로 해야 한다.
- 코드표가 없는 항목 138건과 단위가 정해지지 않은 항목 95건은 원문 텍스트를 보존하는 방식(CodeableConcept.text, valueString)으로 처리한다.
- KR-mCODE 프로파일 canonical(`http://khis.kr/fhir/kcure/...`)과 `ndi:` 네임스페이스 URI는 임시값이다.
