04

표준 매핑 현황

내장 명세 1,255항목 전체 기준

  • KR CDI 수집범위외 17항목은 직접식별자 6, 기관 메타데이터 5, 전송 시 생성 6입니다. 성명처럼 범위외인 R 항목은 경고가 아니라 정보로 보고합니다.
  • mCODE와 KR Core의 기반 리소스가 다른 항목은 167개입니다. 기본 표현은 KR Core 120, mCODE 47로 정했습니다.
  • 매핑 수정안 171건(168항목)은 모두 '후보'입니다. 승인한 건만 다음 빌드에서 명세에 반영되며, 현재 반영된 건은 0건입니다.
  • ARGO Core 미충족 15개는 대부분 면역·호르몬 치료 용량과 종양세포 비율입니다. 약물 필드는 국내 약품코드 → RxNorm 매핑표가 있어야 채울 수 있습니다.

S5 1차 · 2026-10-19

실제 로컬 모델로 '20개 단위 비동기 요청'을 시험했습니다. 앱과 같은 코드 경로(가명처리 추천 → LLM 제안)를 썼고, 합성 병원 추출 컬럼 46개(가상값 10행)로 측정했습니다. 규칙 신뢰도가 '높음'인 6개를 뺀 40개가 LLM으로 갔습니다.

모델Ollama 0.40.5 · qwen2.5:7b-instruct (7.6B, Q4_K_M, 4.7GB)
실행 환경Intel Core Ultra 7 258V · RAM 32GB · CPU 추론(내장 GPU Arc 140V는 Ollama 기본 미지원)
정답 기준컬럼별 허용 기법 목록(예: 날짜 = 날짜 이동 또는 경과일). 규칙 엔진만 쓰면 46개 중 36개 정답

프롬프트 단계별 정확도

규칙만 (36)규칙 + LLM 제안 그대로안전 병합(보호 수준을 낮추는 제안 제외)
단계방식보낸 40개 중 LLM 정답전체 46개안전 병합소요
  • v1 기법을 직접 고르게 하자 병기·검사값·Y/N까지 "식별 정보"로 보고 삭제했습니다(과잉 판정).
  • v2 규칙 추천을 보여 주자 근거에는 "환자 이름"이라고 쓰고도 규칙의 '유지'를 그대로 따랐습니다(앵커링).
  • v3 LLM은 컬럼의 의미 범주 12종만 판정하고, 범주 → 기법은 코드의 정책표가 정합니다. 이 방식에서 크게 좋아졌습니다.
  • v3.1(최종) 약어·나이·자유문 힌트를 넣고, 응답에서 빠진 컬럼만 1회 다시 묻습니다. 보호 수준을 낮추는 제안은 '주의'로 표시하고 일괄 적용에서 뺍니다.
